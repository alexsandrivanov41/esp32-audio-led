# ESP32 Audio Streamer Server

Сервер для приёма аудиопотока с ESP32-WROVER-B устройств на основе прошивки main.ino.

## Функционал

- **WebSocket сервер** (порт 8080) - сигнализация с устройствами
- **UDP сервер** (порт 5004) - приём RTP аудио пакетов
- **HTTP веб-интерфейс** (порт 8081) - мониторинг и управление
- **Поддержка шифрования AES-128-CBC** - дешифрование аудиопотока
- **Сохранение в WAV файлы** - автоматическое сохранение записей
- **REST API** - программное управление

## Установка зависимостей

```bash
pip install -r requirements.txt
```

Или вручную:
```bash
pip install websockets aiohttp cryptography
```

## Запуск сервера

```bash
python3 server.py
```

После запуска сервер будет доступен по адресам:
- WebSocket: `ws://localhost:8080`
- UDP Audio: `udp://localhost:5004`
- Web UI: `http://localhost:8081`

## Веб-интерфейс

Откройте в браузере `http://localhost:8081` для:
- Мониторинга подключенных устройств
- Просмотра статуса записи в реальном времени
- Скачивания аудио файлов (кнопка ⬇️ Download)
- Прослушивания записей прямо в браузере

## REST API

### Получить статус сервера
```bash
GET http://localhost:8081/api/status
```

Ответ:
```json
{
  "server_time": "2024-01-01T12:00:00",
  "connected_devices": 1,
  "devices": [...],
  "total_recordings": 5,
  "total_storage_bytes": 1048576,
  "udp_port": 5004,
  "ws_port": 8080,
  "http_port": 8081
}
```

### Получить список устройств
```bash
GET http://localhost:8081/api/devices
```

### Получить список записей
```bash
GET http://localhost:8081/api/recordings
```

### Управление записью устройства
```bash
POST http://localhost:8081/api/device/{device_id}/action
Content-Type: application/json

{"action": "start_recording"}
```

Действия: `start_recording`, `stop_recording`

### Скачать аудио файл
```bash
GET http://localhost:8081/download/{filename}
```

## Протокол работы

### 1. Регистрация устройства
Устройство отправляет через WebSocket:
```json
{
  "type": "register",
  "id": "esp32-audio",
  "mac": "AA:BB:CC:DD:EE:FF",
  "ssrc": 1,
  "ssl": false
}
```

Сервер отвечает:
```json
{
  "type": "registered",
  "udp_port": 5004,
  "server_time": "2024-01-01T12:00:00"
}
```

### 2. Начало записи
Устройство или сервер могут инициировать запись:
```json
{
  "type": "record",
  "recording": true
}
```

Сервер подтверждает:
```json
{
  "type": "record_ack",
  "recording": true,
  "timestamp": "2024-01-01T12:00:00"
}
```

### 3. Передача аудио
Устройство отправляет RTP пакеты через UDP:
- Заголовок RTP: 12 байт
- Полезная нагрузка: PCM данные (возможно зашифрованные)

Формат RTP заголовка:
- Байты 0-1: Версия и тип полезной нагрузки
- Байты 2-3: Sequence Number (big-endian)
- Байты 4-7: Timestamp (big-endian)
- Байты 8-11: SSRC (big-endian)

### 4. Остановка записи
При остановке записи сервер сохраняет накопленные аудио данные в WAV файл.

## Шифрование

Если на устройстве включено шифрование (SSL/TLS), сервер использует PSK ключ для дешифрования:

- Алгоритм: AES-128-CBC
- Ключ: 16 байт (первые 16 байт из 32-байтного PSK)
- IV: 4 байта sequence number (big-endian) + 12 байт PSK

Для настройки PSK ключа измените `DEFAULT_PSK_HEX` в конфигурации сервера.

## Конфигурация

В начале файла `server.py` можно изменить параметры:

```python
class Config:
    WS_PORT = 8080        # Порт WebSocket
    UDP_PORT = 5004       # Порт UDP для аудио
    HTTP_PORT = 8081      # Порт веб-интерфейса
    AUDIO_DIR = "recordings"  # Директория для сохранения файлов
    SAMPLE_RATE = 16000   # Частота дискретизации (Гц)
    BITS_PER_SAMPLE = 32  # Бит на сэмпл
    CHANNELS = 1          # Количество каналов (моно)
```

- Python 3.8+

## Пример использования

1. Запустите сервер: `python3 server.py`
2. Откройте веб-интерфейс: `http://localhost:8081`
3. Подключите устройство ESP32 (оно автоматически зарегистрируется)
4. Нажмите кнопку записи на устройстве или через API
5. После остановки записи файл появится в списке доступных для скачивания

## Устранение неполадок

### Устройство не подключается
- Проверьте IP адрес сервера в настройках ESP32
- Убедитесь что порты 8080 и 5004 открыты в фаерволе
- Проверьте логи сервера на ошибки подключения

### Аудио не сохраняется
- Убедитесь что команда записи была отправлена (`{"type": "record", "recording": true}`)
- Проверьте что SSPC устройства совпадает с зарегистрированным
- При включенном шифровании убедитесь что PSK ключи совпадают

### Проблемы с декодированием
- Проверьте формат аудио (16kHz, 32-bit, моно)
- При шифровании проверьте правильность PSK ключа
